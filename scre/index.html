Frida

Patch the client's API URL

Using Frida, patch the game binary so its hardcoded API URL (e.g. an ingame.supercell.com-style endpoint) points to your own domain instead. HTTPS is required, so a valid certificate for that domain is mandatory.

const base = Process.getModuleByName("libg.so");
const SCIDPatcher = {
    offsets: [0x0, 0x0, 0x0, 0x0, 0x0], // fill in the actual URL offsets
    init() {
        this.offsets.forEach(offset => {
            Memory.protect(base.add(offset), 256, 'rwx');
            base.add(offset).writeUtf8String("https://your-new-domain.com");
        });
    }
};
The offsets in the original notes are placeholders — you'd need to locate the real string offsets in the binary yourself (e.g. via a disassembler).

nginx

Reverse-proxy the domain to your local server

Redirect plain HTTP to HTTPS, terminate TLS, and forward traffic to whatever local port your backend listens on (7777 in this example):

server {
    listen 80;
    listen [::]:80;
    server_name yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 127.0.0.1:8443 ssl;
    server_name yourdomain.com;

    ssl_certificate /path/to/cert/fullchain.pem;
    ssl_certificate_key /path/to/cert/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;

    location / {
        proxy_pass http://127.0.0.1:7777;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection keep-alive;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Port 443;
        proxy_cache_bypass $http_upgrade;
    }

    error_log /var/log/nginx/error.log;
    access_log /var/log/nginx/access.log;
}

Python

Stand up a basic HTTP listener

Any language works — a minimal Python server that logs every request is enough to start observing traffic:

from http.server import BaseHTTPRequestHandler, HTTPServer

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        print("GET", self.path)
        print(self.headers)
        self.send_response(200)
        self.end_headers()

    def do_POST(self):
        length = int(self.headers.get("Content-Length", 0))
        body = self.rfile.read(length)
        print("POST", self.path)
        print(self.headers)
        print(body.decode(errors="ignore"))
        self.send_response(200)
        self.end_headers()

HTTPServer(("0.0.0.0", 7777), Handler).serve_forever()

Analysis

Capture and reconstruct the protocol

Run the listener and read whatever the client sends, piecing the protocol together request by request. Decompiling the game client's DEX files can help clarify what each endpoint is supposed to receive and return.

The original note adds: it's worth populating placeholder assets on the server so it doesn't look empty, and points to a third-party asset repo for that purpose.
!
Key takeaway

How this architecture works

All game logic runs client-side; the server's only job is to answer with the right-shaped data. That's why intercepting and logging requests is enough to reverse-engineer the expected responses.
